# Price Radar

**Backend-сервис и Telegram-бот для отслеживания цен товаров Wildberries.**

Пользователь добавляет товар или импортирует корзину, выбирает город и условие уведомления. Price Radar периодически проверяет цены, сохраняет историю наблюдений и сообщает о снижении цены или достижении заданного значения.

Проект реализован как модульный монолит на Java и Spring Boot.

## Стек технологий

| Область | Технологии                      |
|---|---------------------------------|
| Backend | Java 21, Spring Boot 3.5 |
| Build | Maven |
| Database | PostgreSQL                      |
| Migrations | Flyway                          |
| Telegram | Telegram Bot API, long polling  |
| Tests | JUnit 5, Testcontainers         |
| Infrastructure | Docker, Docker Compose          |

Взаимодействие с Telegram Bot API реализовано через Java `HttpClient`.

## Возможности

- добавление товаров по ссылке Wildberries;
- отслеживание конкретного размера товара;
- импорт корзины;
- уведомления о снижении цены;
- уведомления при достижении целевой цены;
- история цены;
- фиксация цены для выбранного пользователем города;
- отображение цены с WB Кошельком;
- обработка временного отсутствия товара в наличии;
- обратная связь.

По умолчанию пользователь может одновременно отслеживать до 10 товаров.

## Схема работы

```text
сообщение от пользователя в Telegram
   ↓
получение товара / корзины
   ↓
определение варианта и PriceContext
   ↓
создание WatchTarget + Subscription
   ↓
Scheduler
   ↓
Wildberries
   ↓
PriceSnapshot
   ↓
Notification Decision
   ↓
Transactional Outbox
   ↓
Telegram Bot API
```

Цена каждого товара проверяется несколько раз в сутки. Частота проверок задается в `application.properties`.

## Архитектура

Price Radar — модульный монолит на Spring Boot. Для хранения данных используется СУБД PostgreSQL. Бизнес-логика разделена по функциональным модулям, а внутри них — на `domain`, `application` и `infrastructure`.

### WatchTarget и Subscription

`Subscription` описывает пользовательское отслеживание: кто, какой товар и при каком условии отслеживает.

`WatchTarget` описывает цель проверки: товар, вариант и региональный контекст.

Несколько пользователей могут использовать один `WatchTarget`, поэтому одинаковая цена не запрашивается отдельно для каждой подписки, 
что значительно сокращает число запросов к API Wildberries.

```text
несколько Subscription
        ↓
один WatchTarget
        ↓
один запрос к Wildberries
        ↓
один PriceSnapshot
```

### История цен

Каждое наблюдение сохраняется как `PriceSnapshot`.

Для расчёта статистики используются только корректные наблюдения обычной цены товара без учёта скидки WB Кошелька. 
Периоды отсутствия товара в наличии в расчётах не участвуют.


### Региональный PriceContext

Цена и наличие товара на Wildberries зависят от местоположения.

Пользователь выбирает город, после чего Price Radar определяет региональный контекст Wildberries. 
`WatchTarget` сохраняет собственный `PriceContext`, поэтому история одного отслеживания не смешивает цены разных регионов.

Для поиска городов используется Nominatim на данных OpenStreetMap, результаты кэшируются в PostgreSQL.

### Transactional Outbox

Решение об уведомлении и запись события выполняются в одной транзакции с изменением состояния подписки.

После завершения транзакции отдельный worker отправляет сообщение в Telegram.

```text
PriceSnapshot
    ↓
Decision
    ↓
DB transaction
 ├─ Subscription state
 └─ Outbox event
    ↓
Telegram delivery worker
```

Так бизнес-транзакция не зависит от доступности Telegram в конкретный момент.

Доставка имеет семантику `at-least-once`.
Для защиты от повторной постановки одного и того же события используется `idempotency key`.

## Работа с Wildberries

Price Radar получает данные о товарах и ценах через отдельный слой интеграции с Wildberries.

Для устойчивой работы с внешним API используются:

- ограничение частоты запросов;
- повторные попытки при временных ошибках;
- `cooldown` после ограничений и сбоев;
- `batch`-запросы при импорте корзины;
- кэширование части данных.

## Импорт корзины

Доступны два режима:

**Добавить новые** — добавить только товары, которых ещё нет в активном отслеживании.

**Синхронизировать** — привести список отслеживаемых товаров в соответствие с корзиной.

Синхронизация может завершить существующие отслеживания, поэтому перед применением выполняется подтверждение и повторная проверка актуальности состояния.

Если данные корзины получены не полностью, синхронизация блокируется, чтобы не выполнять опасную операцию на неполных данных.

## Конкурентность и целостность данных

Критичные операции защищены не только на уровне backend-приложения, но и механизмами PostgreSQL.

В частности:
- конкурентные операции защищаются блокировками на уровне БД;
- уникальные ограничения предотвращают дублирование данных;
- критичные обновления выполняются атомарными SQL-операциями;
- перед операциями, изменяющими или завершающими отслеживания, состояние повторно проверяется.


## Состояние проекта и дальнейший план развития

Проект находится на стадии MVP и готовится к первому развёртыванию на сервере и закрытому beta-тестированию.

Ближайшая цель — проверить работу сервиса на небольшой группе пользователей, собрать обратную связь и определить дальнейшие приоритеты на основе реального использования.

В дальнейшем планируется:

1. **Визуализация истории цены**  
   Построение графиков по накопленным `PriceSnapshot` за выбранный период.

2. **Пользовательская инструкция**  
   Добавление короткой и понятной инструкции по основным сценариям работы с ботом.

3. **Поддержка других маркетплейсов**  
   Расширение текущей модели на Ozon и Яндекс Маркет с сохранением общего подхода к отслеживанию, истории цен и уведомлениям.

4. **Интеллектуальный анализ цен**  
   Использование LLM для анализа истории цены и формирования понятных пользователю рекомендаций. В дальнейшем — сравнение предложений между маркетплейсами и поиск похожих товаров.
